# 代码习惯

本文持续记录代码审查中确认的长期习惯。每条规则说明应当采用的写法及其原因，不保存只对单次修改有意义的操作过程。

## 不用自报字段或旁路元数据证明数据正确

不要依赖产物随自身写出的 `contract_version` 等自报字段证明产物有效，也不要从模型对象另取 `voxel_feature_channels` 等旁路元数据后复核产物中的实际数组。这些值与被检查内容通常由同一执行路径产生，不能提供独立证据，还会迫使调用方传递冗余参数。

- 直接检查实际数组的数据类型、维数、各轴长度、offsets 对齐和字段间关系。
- 非空 `voxel_final` 的通道数直接读取其第二维；不同 entry 的尾部形状必须由实际数组相互核对。
- 完全空的归档没有可观察到的特征通道数时，使用 `(0, 0)` 表达“行数和通道数均未知或为空”，不要从 checkpoint 配置伪造通道宽度。
- 只有来自独立权威来源的事实才能作为额外校验依据；与产物同源的版本字符串、重复参数或模型属性不能代替内容校验。

## 结构化返回值的 Docstring 必须覆盖完整字段契约

对返回 `dict[str, np.ndarray]` 或类似结构化归档的函数，Docstring 必须按公共字段、变长 `offsets` 与 value 字段、固定形状数组、角色专属字段和条件字段分组；每个字段写明数据类型、形状、具体语义以及与其他字段的对齐关系。

- `offsets` 不能单独列出，必须同时列出它切分的索引、坐标、概率和特征字段。
- 角色专属字段和模型条件字段必须明确出现条件，例如 `CLG_centered` 的候选成员关系、`Selected_Refined_Centered` 的状态映射，以及 Find 与 `unet_c1` 的 P/A 模态差异。
- 对同一组数组使用的 `N_entry`、`N_success`、`N_feature` 和各类变长长度，必须在首次出现时说明含义，避免读者只能从实现代码反推字段关系。
- 只负责编码 `offsets` 与索引的辅助函数，必须用一个小例子展示“每个候选项的局部成员列表”如何变成 offsets/index，并说明局部索引相对于哪个 entry 数值段；同时写明越界和重复检查由哪个校验边界负责。

## 注释必须说明接口实体、正式调用者和数据身份

对作为参数传入的 `Callable`、loader、provider 或 callback，注释不能只复述调用签名和“返回映射”。必须说明它是什么接口、当前由哪个正式入口装配、具体实现读取或生成什么，以及返回值属于真实标注、模型预测还是由两者计算出的派生量。

- 当前正式装配位置唯一时，直接点名该调用位置和传入的具体实现；同时区分“装配位置唯一”与循环或多遍处理造成的运行时重复调用。
- 映射必须说明键和值分别代表什么实体，索引作用于哪个数组或网格，并明确真实标注与模型预测的身份，不能只写 `occurrence_id -> voxel index`。
- 线性索引必须同时说明原始轴顺序、展平顺序和换算关系。例如形状 `(D,H,W)` 的 ZYX 网格采用 C-order 时，X 轴变化最快，`(z,y,x)` 对应 `z*H*W + y*W + x`。
- 同一函数同时使用真实标注与模型预测时，分别点名两者的来源文件、字段或计算步骤，不用“输入”“数据”“结果”等笼统词替代。

## 不用薄包装伪造解耦

依赖是否存在由运行时调用关系决定，不由类型别名、闭包或 callback 的名字决定。领域函数最终需要 Dataset、PyTorch 和模型 wrapper 时，应当把 wrapper、批量构造器及运行参数作为真实依赖直接传入，不要再包一层只转发一次调用的 `FullForwardCallback`，也不要声称这种包装“消除了依赖”。

- 只做一次字段访问、数组转换或参数转发的函数直接内联；不要用函数名替代一行可以完整读懂的代码。
- 只有承担领域变换、被多处复用或形成明确副作用边界的逻辑才单独成函数。
- 测试便利不能反向塑造正式接口。测试桩必须实现正式 wrapper 输出和 Dataset/Collator batch 契约，不在生产函数中增加 `output_adapter`、旁路 hook 或测试专用回调。
- 可以保留外层 `RoleProducer` 这类真正隔离调度与领域生产的边界；不要把它机械地复制到领域函数内部每一层。

## 函数职责概括不限制篇幅

函数和模块都应做足以让读者理解职责、输入、输出、关键阶段和分支的概括。概括不限制句数、长度或组织形式；如果一个函数包含多个阶段，就逐阶段说明，不要为了满足“一句话”而写空泛摘要。

## 大文件按冷读工具和业务演进布局

当一个模块同时包含底层转换、领域组装和多个正式入口时，文件前半部分放可独立冷读的工具函数，随后使用一行 `# ================================================` 分隔，后半部分按主流程的业务演进顺序排列正式入口。主流程中的每一步应尽量直接展示真实调用，不能通过多层包装函数隐藏关键转换。

- 单次调用、简单字段映射、参数转发和一行转换默认内联。
- 只有独立领域变换、稳定复用、独立副作用或明确测试边界才保留函数。
- 函数在文件中的位置应服务于阅读顺序，而不是按生成时间或局部修改顺序堆放。

## 代码结构以审查资源为重要优化指标

在本项目中，嵌套次数、正文代码量和函数数目都视为与人类审查者的理解资源消耗成正比的结构成本。这不是单纯的个人风格偏好，而是与代码可审查性、维护成本和错误发现速度直接相关的重要优化指标。

- 嵌套次数越多，读者需要同时记住的局部上下文、分支前提和数据状态越多；应优先减少无业务意义的条件、循环和调用层级。
- 正文代码量越大，主数据流越容易被防御性分支、重复转换和样板代码遮蔽；应让每一段可见代码都对应清晰的领域阶段或数据变换。
- 函数数目越多，读者需要跳转和维护的调用关系越多；单次调用、简单转发和一行转换不应单独成函数，只有真实职责边界才值得保留。
- 不能用更多包装函数、闭包或回调把代码量和嵌套转移到别处；审查成本按读者实际需要追踪的调用图计算，而不是按当前函数表面的行数计算。

## GPU 批量大小属于正式性能契约

当 Dataset collator 和模型已经支持批量输入时，不得在正式推理路径中硬写 `batch_size=1`。吞吐量不是实现细节；把可并行工作串行化会直接改变工程可用性。

- centered 完整 forward 的正式默认批量大小是 12，并通过 `--centered-batch-size` 显式可调。
- 稠密 V 网格按 batch 第 0 维拆分；变长 A 表按模型 forward 后的 `atom_counts` 连续段拆分；变长 P 表按 `anchor_batch_index` 的归属拆分。不能假定不同 BOX 的 A/P 行数相同。
- 测试至少覆盖一个跨批量边界的请求序列，例如 13 个 BOX 在批量 12 下必须形成 `12 + 1` 两次 forward；只断言参数默认值不算验证 GPU 批量真实生效。
- 执行批量不能改变归档顺序、`centered_box_index`、offsets 或来源身份；拆分后的逐 BOX payload 必须与请求顺序一致。

## 正式内部代码不重复手写契约校验

受控推理和数据组装函数的正文中，手写 `raise` 与防御性代码几乎不得出现。当前代码中这类分支已经接近正文代码量的三分之一，也消耗人类审查者接近三分之一的理解资源；它们把主要数据流切碎，让审查者必须反复判断“这是业务分支，还是 AI 为假想坏输入添加的保护”。

正文应直接表达已由上游建立的数据契约和领域状态。契约不成立时，优先在测试中暴露；外部输入、文件读取、发布边界和不可逆副作用前的集中校验另行保留，不能把这些边界校验复制到每个内部函数。

受控内部函数默认相信上游已经建立的数据契约。不要为字段存在、dtype、shape、列表对齐或参数取值重复手写 `raise`，也不要把这些 `raise` 换成 `assert`；这些性质由测试和正式发布边界的归档校验器负责。

- 一行转换或字段读取后紧跟 shape/type 校验的辅助函数应删除并内联，正确与错误形状都在测试中覆盖。
- 外部文件、用户命令行输入和发布前归档属于边界，可以保留集中、可解释的校验；不可逆写入或昂贵外部副作用前也可以拒绝不合法输入。
- `empty`、`no_overlap` 等预期领域状态使用显式状态表达。模型 forward 或实现错误必须自然向上传播，使整个角色不发布 `_COMPLETE`；不得用 `except Exception` 吞掉后伪造一个 `failed` 数据项。
- 模型输出只读取当前权威直键。不要在正式代码中逐层猜测 `voxel_features`、`voxel_outputs` 等多个候选位置；历史兼容只能集中在明确的读入边界。

## 注释条目必须展开到可执行的数据契约

Docstring 中的参数和返回条目不能只写“当前 PDB 几何”“批量物化请求”“生成 payload”或“追加特征”。这种描述没有告诉读者数据究竟是什么，也无法据此编写调用代码或测试。

- 对数组写明 dtype、完整 shape、轴顺序、单位和数值身份；对变长表写明第一维与哪个 offsets 或归属索引对齐。
- 对 `CenteredGeometry` 等结构对象展开其关键字段，例如完整图 `(D,H,W)` ZYX shape、世界 XYZ 角点原点、XYZ 体素尺寸和固定 80³ BOX。
- 对 batch builder 写明输入是同一 producer、split、PDB 和 role 的有序 `CenteredRequest` 序列，输出是训练同源 Collator 生成并已搬到目标设备的 batch；不能只写“Dataset 入口”。
- 对结构化返回值必须逐键说明，不能用“V/P/A 表”“其余字段”“同上”代替：共同身份/几何字段、每个 V/P/A 键、每个 membership/offsets 键和角色状态键都要单独出现，并说明顺序与来源身份。
