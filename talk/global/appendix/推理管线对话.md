## 1. 当前 Gaussian 数学上不能按你说的方式退化

当前分数是：

\[
S=S_{\text{basic}}
+\lambda_+\sum_i w_i p_i
-\lambda_-\sum_i w_i(1-p_i)
\]

见 [scoring.py](C:/Users/15919/Desktop/AUTO/Pocket_Plus-v3-macro/src/inference/scoring.py:127)。

把它展开：

\[
S=S_{\text{basic}}
+(\lambda_++\lambda_-)\sum_iw_ip_i
-\lambda_-\sum_iw_i
\]

因此：

- 如果你说的“原子概率为 0”是 \(p_i=0\)，分数不会退化为 basic，而会变成  
  \(S_{\text{basic}}-\lambda_-\sum_iw_i\)，即受到最大负惩罚。
- 只有同时令 \(\lambda_+=\lambda_-=0\)，才会在共同候选集合内退化为 basic。
- 当前搜索网格不包含 0：细化后最小正、负系数仍分别是 `0.0128` 和 `0.0008`，见 [stage1_v3.yaml](C:/Users/15919/Desktop/AUTO/Pocket_Plus-v3-macro/configs/inference/stage1_v3.yaml:37)。

如果你原意确实是“原子预测为 0 就不产生影响”，那么现有负项定义违背了原始设计。最简单的正确形式应是：

\[
S=S_{\text{basic}}+gE_{\text{atom}},\qquad g\in\{0,\ldots\}
\]

其中 `g=0` 是显式 basic 分支。

这说明：

- centered 体素概率均值几乎没有判别能力；它在命中/未命中候选上分别约为 `0.9854/0.9836`，基本饱和。
- 当前昂贵的 centered 前向在打分中实际只消费原子概率，`centered_probability` 并未进入最终公式。

但当前原子聚合还有明显问题：

- 每个候选的原子数中位数为 283，最大达到 1,026。
- Gaussian 修正与原子数量的 Spearman 相关系数约 `0.503`。
- 公式没有除以原子数或 \(\sum w\)，因此它同时测量“附近原子是否可信”和“附近有多少原子”。
- 原子概率中位数只有 `0.00014`，99% 分位却约 `0.994`，高度两极化。
- 原子验证 PRAUC 为 `0.57555`，有信号但不算强。
- 原子头使用 Focal+Tversky 训练；这类损失适合分类/分割，却不保证 sigmoid 数值是经过校准的真实概率。直接把 \(p\) 与 \(1-p\) 当作正负证据并不稳妥。

这解释了为什么它在 F2 候选较多、噪声较大的情况下更有效：

- F1 语义阈值 `0.674866`，产生 1,049 个 blobs，basic 已经较干净。
- F2 语义阈值 `0.204956`，产生 1,510 个 blobs，Gaussian 有更多错误候选可以排除或重排。
- F2-beta1 的固定 macro F1 总分从 `1.510681` 提高到 `1.602254`。
- F2-beta2 的固定 macro F1 总分从 `1.460061` 提高到 `1.549484`。

因此，Gaussian 并不是“效果很差”，而是更像一个在低语义阈值下有价值的候选重排器。

## 4. 推荐处理顺序

第一步必须修复比较契约，不需要重新训练：

1. 始终以完整 blobs 作为权威候选集合。
2. centered 原子信息通过 `source_blob_index` 附加到可处理候选。
3. 无法 centered 的候选令原子增量为 0，保留 basic 分数。
4. 增加显式 `atom_gate=0` 分支。
5. 每个 Gaussian 参数组合都像 basic 一样扫描真实候选分数断点，不再使用粗糙的固定阈值网格。
6. 建立回归门禁：`atom_gate=0` 时，选择掩码、逐 PDB 指标和总分必须与 basic 逐项完全一致。

随后再改进原子证据。我推荐优先尝试归一化对比，而不是继续扩大 λ 网格：

\[
q_{\text{near}}=
\frac{\sum_i w_i p_i}{\sum_i w_i+\epsilon}
\]

进一步可以使用：

\[
E_{\text{atom}}=
q_{\text{near}}-q_{\text{shell}}
\]

其中 `q_shell` 是离候选稍远的一圈受体原子的平均预测。这样测量的是“候选附近是否比同一 PDB 的局部背景更像结合区域”，而不是附近有多少原子。

更完整但仍轻量的形式是：

\[
S=S_{\text{basic}}+
g\cdot
\frac{n_{\text{eff}}}{n_{\text{eff}}+k}
\cdot(q_{\text{near}}-q_{\text{shell}})
\]

其中 `g=0` 保证 basic 是严格可达端点，可靠性因子防止只有一两个原子的候选产生过大修正。

最后还有一个更本质的结构问题：同一个候选选择掩码现在同时服务语义区域和对象检测。`9gc2` 的巨大区域是优秀的语义预测，却不是优秀的单对象候选。更合理的长期方案是：

- semantic mask：主要由体素概率、区域大小决定；
- object candidate list：由 Gaussian 原子证据重排；
- 两者分别计算语义指标和 coverage/one-to-one 指标。

这会比强迫一个标量阈值同时优化“区域并集”和“离散对象”更符合任务本身。

最后，即使把 basic 纳入 Gaussian 参数空间，也只能保证在调参集上不低于 basic，不能保证未见数据上稳定超过。当前 Gaussian 一组绝对阈值组合约涉及 500 个粗网格、375 个细网格和 33 个体素门槛，却只在同一批 30 个 PDB 上选择并汇报。最终应使用按 PDB 分组的交叉验证或独立 held-out 集合，报告逐 PDB 配对差值和置信区间。

我的总体判断是：**不应放弃 Gaussian 原子打分；先修复候选域和 basic 恒等分支，再做归一化与分任务选择。现有数据已经证明原子证据有用，只是当前实现没有公平地兑现你的原始设计。**
