# 分子对接工具与环境说明

本文档记录 Pocket Plus 分子对接任务当前依赖的服务器环境、Rosetta 工具、数据路径和关键命令。它服务于后续 AI agent 接手，不追求覆盖 Rosetta 全部功能，只记录已经验证过的路径和工作方式。

## 服务器连接

Windows 本地 SSH 配置中可用入口为：

```text
Host 10.102.33.220
  Port 10022
  HostName 10.102.33.220
  User penghongen
  IdentityFile ~/.ssh/id_rsa
```

示例：

```powershell
ssh 10.102.33.220
```

注意：从 Windows 通过 SSH 传递中文路径时，曾出现中文目录被替换为字面量 `??????` 的问题。后续脚本在服务器端构造中文路径时，应优先使用 Python Unicode 转义，例如：

```python
allowed = Path("/home/penghongen") / "\u5206\u5b50\u5bf9\u63a5\u5c1d\u8bd5"
```

该路径即：

```text
/home/penghongen/分子对接尝试
```

## 推理结果路径

第一阶段使用的模型输出为：

```text
/home/penghongen/My_Project/feedback_plus/infer_out/ligand_base2_new/stage2_threshold_component_policy
```

每个样本目录通常包含：

```text
summary.json
metrics.json
voxel_candidates.json
instance_label_filtered.npz
ligand_mask_filtered.npz
ligand_pred.npz
receptor_pred.npz
```

`summary.json` 中的 `cache_path` 指向 infer cache，例如：

```text
/home/penghongen/My_Project/feedback_plus/infer_cache/ligand_base2_new/7zdf.npz
```

cache 的 `meta_json` 中需要读取：

- `map_path`：真实 EMDB map，用于 docking density。
- `sim_map_path`：cryoatom receptor 的模拟 map，本轮 docking 不使用。
- `cif_path`：cryoatom 预测结构。
- `cif_gt_path`：真实结构参考路径，不一定适合作为 receptor。

## ligand mapping

候选 ligand 来自：

```text
/storage/penghongen/CIF_Ligand/mapping/ligand_mapping.csv
```

第一阶段使用的候选定义：

```text
pdb_id == 当前样本
status == PASS_HIGH
emerald_id_input_status == FORMAT_OK_FOR_LIBRARY_ENTRY
native_mol2_path 非空且文件存在
mol2_heavy_atoms > 1
CCD 不是独立金属离子
```

独立金属离子不进入 docking，例如 `MG`、`ZN`、`FE` 等。若 ligand 内部含金属原子，例如 heme 类或 `7zdf` 的 `ISW` 含 `FE`，可以运行，但结果需要标记风险。

## receptor 来源

当前每个样本使用两套 receptor：

1. `true_receptor`
   来自真实结构去配体版本，优先路径：

   ```text
   /storage/chenzhaoyang/cryo_em/CIF_3.5_atom/{PDB_ID}.cif
   ```

2. `cryoatom_receptor`
   来自 cryoatom 根据真实 map 建模得到的结构：

   ```text
   /storage/chenzhaoyang/cryo_em/result_split/{pdb_id_lower}/{pdb_id_lower}.cif
   ```

Rosetta 读取 cryoatom CIF 时曾因为两字符 author chain ID 失败，因此当前流程会在允许目录中把 CIF 转成单字符 chain 的 PDB，再交给 Rosetta。

## 已验证 Rosetta 参数

低成本 smoke test 使用 `GALigandDock`，核心 XML 参数为：

```xml
<GALigandDock
  name="dock"
  scorefxn="ga"
  scorefxn_relax="ga"
  runmode="VSX"
  reference_pool="map"
  grid_radius="8.0"
  grid_step="0.5"
  padding="4.0"
  sidechains="none"
  nrelax="1"
  nreport="1"
  estimate_dG="true"
  entropy_method="Simple"
  local_resolution="样本分辨率"
  skeleton_radius="8.0"
  method_for_radius="fixed"
  random_oversample="1.0"
  reference_oversample="1.0"
  reference_frac="0.8"
  debug_report="true"
  use_pharmacophore="false">
  <Stage repeats="1" npool="12" smoothing="0.5" elec_scale="1.0"
         pmut="0.2" rmsdthreshold="2.0" maxiter="20" pack_cycles="5"/>
</GALigandDock>
```

命令行必须包含：

```bash
-corrections::gen_potential true
```

否则 `beta_genpot` 会报错退出。

`reference_pool="map"` 与默认 pharmacophore docking 冲突，因此必须显式：

```xml
use_pharmacophore="false"
```

## 最小命令形态

示例命令：

```bash
/home/penghongen/software/rosetta/bin/rosetta_scripts_430 \
  -database /home/penghongen/software/rosetta/source_build/rosetta.source.release-430/main/database \
  -s complex.pdb \
  -parser:protocol gadock_density_smoke.xml \
  -extra_res_fa L01.params \
  -edensity:mapfile /storage/chenzhaoyang/cryo_em/EMDB_3.5_cc/emd_xxxxx.map \
  -edensity:mapreso 3.0 \
  -edensity:cryoem_scatterers true \
  -corrections::gen_potential true \
  -out:path:all outputs/site001/true_receptor_L01 \
  -out:file:scorefile true_receptor_L01_site001_score.sc \
  -nstruct 1 \
  -overwrite
```

## 输出字段

当前 scorefile 已观察到这些字段：

```text
total_score
score
-TdS
complexscore
dG
dH
lig_dens
lig_rms
ligscore
recscore
ligandname
description
```

本阶段主要读取：

- `dG`：Rosetta 估计结合自由能，当前只用于相对排序。
- `dH`：焓项。
- `-TdS`：简单熵项。
- `lig_dens`：ligand 与密度相关的字段。
- `ligscore`：ligand 局部分数。

## 资源约束

用户允许：

- CPU 作业，但不要超过 36 核。
- A100 作业，但不要超过 3 张。
- 不申请其他 GPU。

当前已完成的 smoke test 只使用 CPU，并且并发进程数远小于 36。
