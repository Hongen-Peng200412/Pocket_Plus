## 为什么修改代码

1. 现有 CLI 只把顶层 JSON 列表解释成 PDB 标识；held-out `test_0.json` 的顶层是包含 `pdb_ids` 的对象，因此正式入口必须读取这两种已知清单结构。
2. 现有完整图推理为每个 PDB 重建 CPU 物化线程池，也不在当前 PDB 收尾时准备下一 PDB 的几何与首个 batch；本次把 AUTO 仓库已经验证的跨 PDB 线程复用和首批预取移入正式主线，但不引入实验专用产物字段。
3. 现有 centered 只让 `fits_centered_box=true` 的 blob 前向，导致无法被单个 80³ BOX 完整包络的大 blob 从 Gaussian 候选集合消失；本次让它们与普通 blob 一样执行合法 80³ 居中裁块前向，并在 centered NPZ 明确保存完整 blob 是否可包络以及完整体素数。框外来源体素不伪造概率或特征，候选选择和评估继续使用完整 blobs 事实。
4. 现有 Gaussian 两个 lambda 网格不含 0，且分数阈值采用固定粗网格和乘数细化；本次让两个 lambda 都包含 0，并对每个 tau/lambda 组合扫描实际 float32 候选分数断点，使 basic 成为可达端点且阈值选择与 basic 同口径。
5. 现有评估只有 semantic PRAUC；本次对 coverage 和 one-to-one 在 0.3、0.5、0.6 三个双向覆盖阈值下增加 micro 与 PDB 等权 macro PRAUC。PRAUC 固定使用已冻结的两个体素数门槛，但忽略最终 `score_threshold`，按实际 float32 候选分数降序并合并相同分数。
