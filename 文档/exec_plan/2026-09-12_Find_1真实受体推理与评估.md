# Find_1 真实受体推理与评估执行记录

本文记录 `Find_1` 模型在真实受体数据上的 Stage1 校准、选参与 held-out 测试，包括冻结模型来源、正式命令、Slurm 资源、产物目录、门控证据和最终结果。任务依据 `talk/global/global_8.30.md` 的“小改推理管线”和“训练 Find_1”背景执行，并沿用 `文档/exec_plan/2026-09-02_unet_c1三种采样模型推理与测试.md` 已冻结的 `unet_c1` 比较口径。

本任务不继续训练 `Find_1`，不动态选择更晚 checkpoint，也不改变 Stage1 指标公式。基础打分与 Gaussian 打分使用同一模型、同一 calibration 概率图和同一 `test_0` 概率图；`test_1` 只从 `test_0` 的逐 PDB 评估事实按原顺序派生，不再次执行模型前向。

## 科学口径

| 流水线 | 语义阈值 | 候选评分 | 选参目标 | 正式测试 |
| --- | --- | --- | --- | --- |
| 基础打分 | 在 calibration 上最大化 PDB 等权 macro semantic F1 | `source_probability_mean` | `objective_beta=1`，最大化 macro semantic F1、coverage F1@0.3 与 one-to-one F1@0.3 之和 | 使用冻结的 F1 semantic 与 F1 basic 参数评估 `test_0` |
| Gaussian 打分 | 在同一 calibration 概率图上最大化 PDB 等权 macro semantic F2 | 对 F2 blobs 执行 centered 前向后使用 Find Gaussian 分数 | `objective_beta=1`，仍最大化上述三项 macro F1 之和 | 使用冻结的 F2 semantic 与 F2 Gaussian 参数评估 `test_0` |

两条流水线均固定 `prefiltered_min_voxel=8`；centered 使用 `forward_min_voxels=8`。任何 PDB 即使候选数严格大于 1,000，也只写 `_BLOB_EXCEED` 提示标记并继续，不因候选数被排除。`test_1` 是 `test_0` 的 149-PDB 保序子集，不是第二次独立推理，也不是与 `test_0` 独立的统计样本。

## 为什么修改 Pocket Plus

1. 现有 `stage1_v3.sh` 已能完成 probability、blobs、centered、tune 与 evaluate，但缺少一条把本任务两套固定科学流程编排起来的短命令。新增正式 shell 只组合既有官方阶段，不新增评分公式或 CLI 参数。
2. Job `368455` 提供两张 H100 和 64 个 CPU。通用 `configs/inference/stage1_v3.yaml` 需要把完整图 batch 固定为 24、centered batch 固定为 12，并按每张 GPU 约 32 个 CPU 的资源边界调整外层线程数。
3. `test_1` 不应重复执行推理。任务专用临时脚本将直接调用正式聚合函数，从 `test_0` 的逐 PDB 评估事实得到同字段契约的 149-PDB 汇总，并明确记录派生关系。长期 shell 与 Learn 测试不调用 `tmp/`；临时脚本只在 `test_0` 正式入口成功结束并重新进入 `try_lock` 后，由下一条一次性动态命令执行。
4. 服务器共享项目中的 `src/inference/evaluation.py` 早于当前 Learn 分支的 P/R 汇报契约；启动前只从完成双线等价核验的 Learn 状态安全同步，不手工复制第二套指标实现。
