# 测试 pipeline 运行指导

本文说明如何在服务器上运行测试 pipeline，以及每一步会得到什么、为什么要这样做。指标和配置口径见 `general.md`。

> 运行环境以 Linux 服务器为准。本地 Windows 主要用于改代码、轻量静态检查和同步，不建议跑完整 DL forward、phenix 或 18 套评估。

### 1.2 激活环境

如环境名或路径有变，以服务器实际环境为准。

## 2. 先跑一个 DL smoke test

正式批量运行前，先用一组已存在 cache 的 DL 配置做最小验证，确认：

1. 能读取 `feedback_plus/infer_cache/...` 中的预测缓存。
2. 能把评估结果写到 `EVAL_OUT`。
3. 输出字段是 `cov03/cov06`。
4. `protein_110` fixed test 有 `pr_auc_macro`、per-sample `pr_auc` 与 loose instance 指标。

示例：

```bash
python src/inference/main/two_stage_basic.py \
  --val_config DL/emb_unet_stardard_40 \
  --test_config DL/emb_unet_stardard
```

如果需要指定设备：

```bash
python src/inference/main/two_stage_basic.py \
  --val_config DL/emb_unet_stardard_40 \
  --test_config DL/emb_unet_stardard \
  device=cuda:0
```

### 2.1 这一步会做什么

这条命令会运行三段：

```text
protein_40 Stage1：只扫 threshold，objective=avg_voxel_f1
protein_40 Stage2：局部扫 threshold，objective=avg_voxel_f1 + global_instance_f1_cov03 + global_instance_f1_cov06
protein_110 fixed test：固定 Stage2 best params，只评估，不扫参，额外计算 PR-AUC
```

### 2.2 这一步会得到什么

以 `emb_unet_stardard` 为例，主要输出在：

```text
/home/penghongen/My_Project/EVAL_OUT/infer_out/emb_unet_stardard_40/stage1_threshold_only/
/home/penghongen/My_Project/EVAL_OUT/infer_out/emb_unet_stardard_40/stage2_threshold_component_policy/
/home/penghongen/My_Project/EVAL_OUT/infer_out/emb_unet_stardard/
/home/penghongen/My_Project/EVAL_OUT/infer_out/emb_unet_stardard_40/two_stage_basic_summary.json
```

其中：

```text
stage1_threshold_only/best_params.json
  protein_40 上按 voxel F1 选出的粗阈值。

stage2_threshold_component_policy/best_params.json
  protein_40 上选择出的后处理参数，test 会固定复用。

emb_unet_stardard/best_summary.json
  protein_110 held-out test 的汇总指标。

two_stage_basic_summary.json
  三段目录、Stage1 阈值、Stage2 best params、test 配置摘要。
```

### 2.3 smoke test 重点检查

建议检查：

```bash
python - <<'PY'
import json
from pathlib import Path
p = Path('/home/penghongen/My_Project/EVAL_OUT/infer_out/emb_unet_stardard/best_summary.json')
s = json.loads(p.read_text())
for k in [
    'avg_voxel_f1',
    'global_instance_f1_cov03',
    'global_instance_f1_cov06',

    'global_instance_f1_loose_cov06',
    'top3_success_ratio_cov03',
    'top3_success_ratio_cov06',
    'pr_auc_macro',
]:
    print(k, s.get(k))
PY
```

如果这些字段存在，就说明新口径已进入 test 汇总。

## 3. 批量运行 16 个 DL 配置

DL 配置位于：

```text
configs/infer_or_eval/DL/
```

可运行的 8 对 val/test：

```text
emb_unet_stardard_40      -> emb_unet_stardard
emb_unet_strict_40        -> emb_unet_strict
unet_base_stardard_40     -> unet_base_stardard
unet_base_strict_40       -> unet_base_strict
unet_c1_stardard_40       -> unet_c1_stardard
unet_c1_strict_40         -> unet_c1_strict
unet_c2_stardard_40       -> unet_c2_stardard
unet_c2_strict_40         -> unet_c2_strict
```

批量脚本示例：

```bash
set -euo pipefail
cd /home/penghongen/My_Project/Pocket_Plus

for name in \
  emb_unet_stardard \
  emb_unet_strict \
  unet_base_stardard \
  unet_base_strict \
  unet_c1_stardard \
  unet_c1_strict \
  unet_c2_stardard \
  unet_c2_strict
  do
    echo "========== DL ${name} =========="
    python src/inference/main/two_stage_basic.py \
      --val_config "DL/${name}_40" \
      --test_config "DL/${name}" \
      device=cuda:0
  done
```

### 3.1 DL 批量运行的意义

这一步会给每个 DL 模型 × 系统产生一套 held-out test 指标。如果 cache 存在，主要成本是后处理与评估，而不是 GPU forward。

结果可以回答：

1. 同一系统内，不同 DL 模型谁的 held-out voxel / instance / top-K / PR-AUC 更好。
2. 同一模型在 `stardard` 和 `strict` 两个系统下差异有多大。
3. `protein_40` 选出的阈值迁移到 `protein_110` 是否稳定。

## 4. phenix 差图预生成

phenix baseline 依赖外部二进制，先独立预生成并对齐差图，再由 baseline cache 生成脚本消费。

默认命令：

```bash
python src/inference/main/generate_phenix_diff_maps.py \
  --phenix_output_root /home/penghongen/My_Project/EVAL_OUT/phenix_diff_maps \
  --val_json /home/penghongen/My_Project/Pocket_Plus/src/inference/utils/protein_40.json \
  --test_json /home/penghongen/My_Project/Pocket_Plus/src/inference/utils/protein_110.json \
  --systems stardard strict
```

如果服务器 phenix 路径或 resolution CSV 不同，显式覆盖：

```bash
python src/inference/main/generate_phenix_diff_maps.py \
  --phenix_output_root /home/penghongen/My_Project/EVAL_OUT/phenix_diff_maps \
  --phenix_bin /home/yangjy/software/phenix/build/bin/phenix.real_space_diff_map \
  --resolution_csv /home/penghongen/My_Project/Data/EMDB_PDB_resolution_3.5.csv \
  --val_json /home/penghongen/My_Project/Pocket_Plus/src/inference/utils/protein_40.json \
  --test_json /home/penghongen/My_Project/Pocket_Plus/src/inference/utils/protein_110.json \
  --systems stardard strict
```

默认会跳过已存在的对齐差图。若需要重算，加：

```bash
--no_skip_existing
```

### 4.1 这一步会得到什么

输出结构：

```text
/home/penghongen/My_Project/EVAL_OUT/phenix_diff_maps/
  stardard/<sample_name>/phenix_diff_aligned.mrc
  strict/<sample_name>/phenix_diff_aligned.mrc
  generate_summary.json
```

### 4.2 这一步的意义

phenix 是外部程序，失败模式和 Python 内部 pipeline 不同。先预生成可以：

1. 把 phenix 环境问题、结构输入问题、resolution 问题提前暴露。
2. 让正式 baseline 评估阶段只消费对齐后的 MRC，避免评估过程中混入外部二进制失败。
3. 让 `phenix_real_space_diff_map` 与其他 density-channel baseline 进入同一套 DL-compatible cache 与评估流程。

```text
posdiff_clipnorm_DoG2
```

```bash
python src/inference/main/run_baseline_two_stage.py \
```

```bash
  --phenix_output_root /home/penghongen/My_Project/EVAL_OUT/phenix_diff_maps \
  --systems stardard \
  --baselines phenix_real_space_diff_map \
  --device cuda:0
```

### 5.1 baseline 会做什么

对每个 baseline × system：

1. 为 `protein_40` 生成 baseline DL-compatible cache（首次运行会在 `EVAL_OUT/infer_cache/baseline/` 下生成）。
2. 对 raw score 做每样本内部 rank equalization 到 `[0,1]`。
3. 走 `protein_40 Stage1` 高分位 threshold 粗扫。
4. 走 `protein_40 Stage2` 高分位局部 threshold 选择。
5. 为 `protein_110` 生成 baseline DL-compatible cache。
6. 在 `protein_110` 上固定 Stage2 best params 做 held-out test。

### 5.2 baseline 输出在哪里

以 `diff_clipnorm_nopost_stardard` 为例：

```text
/home/penghongen/My_Project/EVAL_OUT/infer_cache/baseline/diff_clipnorm_nopost_stardard_40/
/home/penghongen/My_Project/EVAL_OUT/infer_cache/baseline/diff_clipnorm_nopost_stardard_110/

/home/penghongen/My_Project/EVAL_OUT/infer_out/baseline/diff_clipnorm_nopost_stardard_40/
/home/penghongen/My_Project/EVAL_OUT/infer_out/baseline/diff_clipnorm_nopost_stardard_110/

/home/penghongen/My_Project/EVAL_OUT/infer_vis/baseline/diff_clipnorm_nopost_stardard_40/
/home/penghongen/My_Project/EVAL_OUT/infer_vis/baseline/diff_clipnorm_nopost_stardard_110/

/home/penghongen/My_Project/EVAL_OUT/infer_error/baseline/diff_clipnorm_nopost_stardard_40/
/home/penghongen/My_Project/EVAL_OUT/infer_error/baseline/diff_clipnorm_nopost_stardard_110/
```

`_40` 输出根下同样有：

```text
stage1_threshold_only/
stage2_threshold_component_policy/
two_stage_basic_summary.json
```

`_110` 输出根下是 fixed test 结果：

```text
best_params.json
best_summary.json
per_sample_best_metrics.json
best_outputs/
```

### 5.3 baseline 的意义

baseline 结果用于回答：

1. DL 模型相对于传统差图/密度通道启发式方法是否有稳定优势。
2. phenix real-space diff map 与简单 density-channel baseline 的差异。
3. `stardard` 和 `strict` 两个系统下，非 DL 方法受结构来源影响的程度。
4. 在完全同一套后处理与评估口径下，模型概率图与 baseline score map 的可比性。

## 6. 推荐执行顺序

完整运行建议顺序：

```text
1. 同步代码到服务器。
2. 激活 conda 环境。
3. 跑一个 DL smoke test。
4. 检查 DL smoke 的 best_summary.json 是否含 cov03/cov06、loose instance 和 pr_auc_macro。
5. 批量跑 8 对 DL 配置。
6. 预生成 phenix 差图。
7. 跑一个 density-channel baseline smoke test。
8. 跑一个 phenix baseline smoke test。
9. 批量跑 12 个 baseline。
10. 汇总 EVAL_OUT 下所有 best_summary.json。
```

## 7. 结果文件怎么读

### 7.1 best_params.json

表示本阶段选择或固定使用的后处理参数。

- Stage1：粗阈值。
- Stage2：选择测试使用的阈值。
- Test：固定使用 Stage2 best params 的副本。

### 7.2 best_summary.json

表示本阶段整套样本的汇总指标。

报告优先看 `protein_110 fixed test` 的 `best_summary.json`，不要用 `protein_40` 的指标当测试性能。

重点字段：

```text
avg_voxel_f1
avg_voxel_precision
avg_voxel_recall

global_instance_f1_cov03
global_instance_precision_cov03
global_instance_recall_cov03

global_instance_f1_cov06
global_instance_precision_cov06
global_instance_recall_cov06

global_instance_f1_loose_cov03
global_instance_precision_loose_cov03
global_instance_recall_loose_cov03

global_instance_f1_loose_cov06
global_instance_precision_loose_cov06
global_instance_recall_loose_cov06

top3_success_ratio_cov03
top4_success_ratio_cov03
top5_success_ratio_cov03

top3_success_ratio_cov06
top4_success_ratio_cov06
top5_success_ratio_cov06

pr_auc_macro
pr_auc_num_valid
```

### 7.3 per_sample_best_metrics.json

保存每个样本在 best params 下的输出目录、候选数和指标。

用途：

1. 找出失败样本或异常样本。
2. 分析某个模型在哪些 PDB/EMDB 上表现差。
3. 结合可视化定位后处理是否过度合并或漏检。

### 7.4 best_outputs/

每个样本的 best params 后处理输出：

```text
ligand_pred.npz
ligand_mask_filtered.npz
instance_label_filtered.npz
voxel_candidates.json
metrics.json
```

用途：

1. 可视化 best params 下的预测 mask / instance。
2. 进一步分析候选体素 blob。
3. 与 PyMOL bundle 或 MRC 输出对应。

### 7.5 infer_vis/

可视化资产目录。baseline 会额外把 raw 差图 sidecar MRC 注册进可视化 bundle，便于同时看：

```text
实验 map
GT 结构
预测 mask / instance
baseline raw diff map（如果有）
```

## 8. 常见错误与排查

### 8.1 找不到 DL cache

症状：运行 DL 时重新 forward，或找不到 `.npz`。

检查：

1. `configs/infer_or_eval/DL/<name>.yaml` 的 `cache_root` 是否仍是 `feedback_plus/infer_cache/...`。
2. `sample_name` 是否与 cache 文件名一致。
3. 配置的 `raw_pairs_json` 是否对应 `protein_40` 或 `protein_110`。

### 8.2 输出还在 feedback_plus

DL 配置应只让 `ckpt_path` 和 `cache_root` 保留 `feedback_plus`，输出相关目录应在 `EVAL_OUT`。

检查：

```bash
grep -R "feedback_plus/infer_out\|feedback_plus/infer_error\|feedback_plus/infer_vis" configs/infer_or_eval/DL
```

应无输出。

### 8.3 objective 字段缺失

`objective_expr` 使用以下字段：

```text
avg_voxel_f1 + global_instance_f1_cov03 + global_instance_f1_cov06
```

检查配置和源码中是否仍引用未产出的 objective 字段：

```bash
grep -R "avg_instance_f1" configs/infer_or_eval/DL src/inference
```

应无输出。

### 8.4 输出字段应为 cov03/cov06

新运行产物使用 `cov03/cov06` 字段。

检查源码和正式配置：

```bash
grep -R "cov04" src/inference configs/infer_or_eval/DL configs/infer_or_eval/non_DL
```

应无输出。

### 8.5 phenix baseline 找不到差图

先确认 phenix 预生成目录：

```text
/home/penghongen/My_Project/EVAL_OUT/phenix_diff_maps/<system>/<sample_name>/phenix_diff_aligned.mrc
```

如果不存在，先运行 `generate_phenix_diff_maps.py`。baseline 消费端不会在线跑 phenix。

## 9. 最小汇总脚本

收集所有 fixed test 的 `best_summary.json` 的简单示例：

```bash
python - <<'PY'
import json
from pathlib import Path

root = Path('/home/penghongen/My_Project/EVAL_OUT/infer_out')
rows = []
for p in root.rglob('best_summary.json'):
    # 跳过 protein_40 的 stage1/stage2，可按路径规则过滤
    if 'stage1_threshold_only' in str(p) or 'stage2_threshold_component_policy' in str(p):
        continue
    s = json.loads(p.read_text())
    rows.append({
        'path': str(p),
        'avg_voxel_f1': s.get('avg_voxel_f1'),
        'global_instance_f1_cov03': s.get('global_instance_f1_cov03'),
        'global_instance_f1_cov06': s.get('global_instance_f1_cov06'),
        'global_instance_f1_loose_cov03': s.get('global_instance_f1_loose_cov03'),
        'global_instance_f1_loose_cov06': s.get('global_instance_f1_loose_cov06'),
        'top3_success_ratio_cov03': s.get('top3_success_ratio_cov03'),
        'top3_success_ratio_cov06': s.get('top3_success_ratio_cov06'),
        'pr_auc_macro': s.get('pr_auc_macro'),
    })

for row in sorted(rows, key=lambda r: r['path']):
    print(json.dumps(row, ensure_ascii=False))
PY
```

这个脚本只做快速巡检；正式表格可后续再整理成 CSV/Excel。
