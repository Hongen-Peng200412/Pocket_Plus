# 测试 pipeline 实施计划

本文描述测试 pipeline 的工程边界和模块分工。运行命令与产物解释见 `运行指导.md`；指标、配置组织和查验清单见 `general.md`。

## 1. 目标

把 DL 模型和六组非 DL baseline 放进同一套流程：

```text
protein_40 Stage1 -> protein_40 Stage2 -> protein_110 fixed test
```

要求：

1. `protein_40.json` 只用于 threshold 校准。
2. `protein_110.json` 只用于 held-out fixed test。
3. DL 与 baseline 共享后处理、扫参、评估指标和输出结构。
4. baseline 先生成 DL-compatible cache，再进入同一套评估流程。
5. 输出保留统一文件：`best_params.json`、`best_summary.json`、`per_sample_best_metrics.json`、`param_search_results.xlsx`、`best_outputs/`。

## 2. 模块分工

| 模块 | 职责 |
| --- | --- |

| `src/inference/main/voxel_pipeline.py` | 构建/读取 cache，调用后处理和评估，写 best outputs、metrics、可视化资产。 |
| `src/inference/voxel_postprocess.py` | 从 ligand probability / score map 生成 mask、instance 和候选 blob。 |
| `src/inference/voxel_tuning.py` | 参数搜索、单组参数评估、summary 汇总、PR-AUC macro 汇总。 |
| `src/inference/voxel_evaluator.py` | voxel、global instance、loose instance、top-K、PR-AUC 指标实现。 |
| `src/inference/main/build_baseline_cache.py` | 生成六组 baseline 的 DL-compatible `.npz` cache。 |
| `src/inference/main/run_baseline_two_stage.py` | 枚举 baseline × system，调用 cache 生成和三段流程。 |
| `src/inference/main/generate_phenix_diff_maps.py` | 预生成并对齐 phenix 差图。 |

## 3. DL 实验

### 3.1 配置范围

DL 配置位于：

```text
configs/infer_or_eval/DL/
```

模型、系统、split 组合：

```text
模型: unet_base / unet_c1 / unet_c2 / emb_unet
系统: stardard / strict
集合: protein_40 / protein_110
总数: 4 x 2 x 2 = 16 个配置
```

`stardard` 和 `strict` 分别使用：

```text
stardard:
  structure_input_source = cif_gt_path
  sim_map_source = sim_map_path
  gt_receptor_source = cif_gt_path

strict:
  structure_input_source = cif_path
  sim_map_source = sim_map_path_cryoatom
  gt_receptor_source = cif_path
```

### 3.2 Stage1

Stage1 只用 voxel F1 粗扫 threshold。

```text
filter_strength = basic
threshold grid = 0.00..1.00 step 0.01
min_component_voxels = 10
connectivity_policy = 7_none
merge_dist = 0.0
vis_enable = false
compute_instance_metrics = false
objective_expr = avg_voxel_f1
```

输出目录：

```text
{output_root}/stage1_threshold_only/
```

### 3.3 Stage2

Stage2 在 Stage1 best threshold 周围做完整评估，选择 test 使用的后处理参数。

```text
filter_strength = basic
threshold window = [stage1_best - 0.10, stage1_best + 0.10]
threshold step = 0.01
min_component_voxels = 10
connectivity_policy = 7_none
merge_dist = 5.0
vis_enable = true
compute_instance_metrics = true
objective_expr = avg_voxel_f1 + global_instance_f1_cov03 + global_instance_f1_cov06
```

输出目录：

```text
{output_root}/stage2_threshold_component_policy/
```

### 3.4 protein_110 fixed test

Test 阶段读取 Stage2 的 `best_params.json`，固定参数评估 `protein_110`。

```text
search_space = {}
compute_instance_metrics = true
compute_pr_auc = true
vis_enable = true
```

输出目录使用 test 配置的 `output_root`，包含：

```text
best_params.json
best_summary.json
per_sample_best_metrics.json
best_outputs/
```

## 4. baseline 实验

### 4.1 baseline family

固定六组：

```text
phenix_real_space_diff_map
diff_clipnorm_nopost
posdiff_clipnorm_DoG1
posdiff_clipnorm_DoG2
posdiff_clipnorm_smooth1
posdiff_clipnorm_smooth2
```

baseline 也按 `stardard` 与 `strict` 两个系统分别运行。

### 4.2 cache 契约

baseline 不直接评估，而是先写 DL-compatible `.npz`：

```text
ligand_pred       = baseline score map after per-sample rank equalization
receptor_pred     = None
hardmask          = 与当前系统结构输入对应的 hardmask
resampled_emdb    = 重采样实验密度图
origin/voxel_size = 网格信息
gt_ligand_mask    = 与 DL 同口径的 GT mask
gt_instance_label = 与 DL 同口径的 GT instance label
meta              = baseline_name / system / score_source / input paths
```

cache 可直接进入：

```text
voxel_postprocess.py
voxel_tuning.py
voxel_evaluator.py
run_voxel_param_search()
```

### 4.3 per-sample rank equalization

每个样本内部将 raw score 映射到 `[0,1]`：

```text
valid_mask = hardmask == 0
score_eq[valid_mask] = (rank - 1) / (N_valid - 1)
score_eq[hardmask > 0] = 0
```

约束：

1. 只在单个样本内部做。
2. 保序，不改变体素间相对大小顺序。
3. hardmask 内置 0。
4. 后续 threshold 作用于均衡后的 score map。

### 4.4 baseline 三段参数

baseline Stage1 使用高分位 threshold grid：

```text
threshold = 0.97..1.00 step 0.0001
```

baseline Stage2 使用局部高分位窗口：

```text
threshold = stage1_best ± 0.001
step = 0.0001
```

其余 Stage1/Stage2/test 流程与 DL 同构。

## 5. Phenix baseline

Phenix 差图先由 `generate_phenix_diff_maps.py` 生成：

```text
phenix_output_root/<system>/<sample_name>/phenix_diff_aligned.mrc
```

生成端负责：

1. 按系统选择 model 和 map。
2. 必要时生成 receptor-only mmCIF。
3. 解析逐样本 resolution。
4. 调用 `phenix.real_space_diff_map`。
5. 将输出差图对齐到 cache 网格。
6. 写 `generate_summary.json` 记录成功、失败、resolution 来源和输出路径。

消费端只按 A2 派生路径读取对齐差图。

## 6. 评估指标

### 6.1 overlap 逻辑

`voxel_evaluator.py` 提供：

```text
build_instance_overlap_stats(pred_instance_label, gt_instance_label)
```

返回：

```text
pred_ids
gt_ids
pred_sizes
gt_sizes
overlap_count_matrix
pred_cover_matrix
gt_cover_matrix
```

有效 pair：

```text
pred_cover >= t AND gt_cover >= t
其中 t in {0.3, 0.6}
```

### 6.2 global instance matching

一对一 Hungarian matching，分数：

```text
sqrt(pred_cover * gt_cover)
```

汇总字段：

```text
global_instance_precision_cov03 / cov06
global_instance_recall_cov03 / cov06
global_instance_f1_cov03 / cov06
```

### 6.3 top-K successful ratio

固定：

```text
K = 3, 4, 5
排序字段 = score_mean
```

单样本 top-K success 表示前 K 个预测 blob 中存在一个与任意 GT instance 构成 valid pair。

### 6.4 PR-AUC

PR-AUC 只在 `protein_110 fixed test` 二分类前景路径计算：

```text
valid = hardmask == 0
score = ligand_pred[valid]
label = gt_ligand_mask[valid]
```

输出：

```text
per-sample pr_auc
best_summary.pr_auc_macro
best_summary.pr_auc_num_valid
```

## 7. 验证计划

每次实现或改配置后至少检查：

1. DL `.npz` cache 能被读取并重新评估。
2. Stage1 只扫 threshold，`vis_enable=false`，`compute_instance_metrics=false`。
3. Stage2 使用 Stage1 best 附近窗口，`vis_enable=true`，`compute_instance_metrics=true`。
4. Test 使用 Stage2 best params，`search_space={}`，`compute_pr_auc=true`。
5. `best_summary.json` 包含 `global_instance_*_cov03/cov06`、loose instance、top-K 和 `pr_auc_macro`。
6. `per_sample_best_metrics.json` 和 `best_outputs/<sample>/metrics.json` 包含 test 阶段 per-sample `pr_auc`。
7. top-K 排序只使用 `score_mean`。
8. baseline cache 与 DL cache 可以进入同一个 `run_voxel_param_search()`。
