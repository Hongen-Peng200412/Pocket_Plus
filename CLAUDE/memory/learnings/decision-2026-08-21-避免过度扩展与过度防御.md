# 避免过度扩展与过度防御

Type: decision
Date: 2026-08-21
Tags: scope, simplicity, defensive-programming

## Context

一次性任务只要求把既有 occurrence 级 split 投影为五份 PDB ID 清单，但实现曾擅自加入汇总文件、完成标记、交叉校验和发布语义，偏离了用户要求。

## Memory

Pocket Plus 的实现必须严格守住用户给定的产物和行为边界：不要过度扩展，不要过度防御。简单任务优先使用直接、易读的最小实现。除非用户明确要求，或存在可以具体说明的高风险问题，否则不得自行增加额外产物、审计协议、完成标记、清单、哈希、备份、复杂校验或抽象层。

## When To Use

编写或修改数据处理脚本、CLI、一次性迁移工具、测试及其文档时，在增加任何用户未点名的行为前先检查本条规则。若新增内容不是完成明确需求所必需，就不要加入；若确有必要，应先说明具体风险并取得用户同意。
