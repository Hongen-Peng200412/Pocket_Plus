# 将代码量视为人的理解成本

Type: decision
Date: 2026-07-26
Tags: human-readable, complexity-budget, training-scripts

## Context

用户会亲自阅读 `训练与运行/sh/` 中直接决定训练行为的脚本。新增代码不仅增加维护成本，也会直接占用用户理解项目的时间和精力。

## Memory

代码量的增加必须被视为人的理解成本。不得仅为了覆盖假设性的异常情况，就在用户需要阅读的训练主线中增加防御代码、抽象层或运行机制。新增逻辑至少应满足一种条件：它是当前必需行为、已有失败证据要求它存在，或用户在理解代价后明确接受。

当现有通用运行器已经保证运行标识唯一时，不应擅自在具体训练脚本中重复增加目录碰撞检查。发现潜在风险时可以解释边界，但用户拒绝该机制后，应保留已确认的精简契约。

## When To Use

- 修改用户会逐行阅读的训练、推理或数据流主线。
- 建议增加防御检查、通用抽象或可复用机制时。
- 在“更完整的工程防护”与“更低的理解成本”之间做取舍时。
