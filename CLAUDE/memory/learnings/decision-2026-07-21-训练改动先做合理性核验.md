# 训练改动先做合理性核验

Type: decision
Date: 2026-07-21
Tags: stage1, training, change-control, scientific-review

## Context

AdaLigand Stage1 正式训练期间，模型、学习率、validation、batch 和资源安排经历了多次用户驱动调整。其中既有基于代码与曲线的新发现，也有一部分受到训练焦虑和即时观察影响。频繁重启会丢失训练进度、增加资源竞争，并可能让短窗口噪声被误判为科学结论。

## Memory

以后用户再次要求修改或重提正式训练时，不应机械执行。先快速核对相关代码语义、resolved config、当前 W&B/本地日志证据、观察窗口是否足够、改动与问题之间是否有明确因果关系，以及重启造成的进度和资源代价。然后明确说明该要求是否合理、证据强弱、主要反例和更小的验证方式；若结论仍不稳，优先建议不终止现有训练的只读核验或短实验。用户确认后再实施。

这不是阻止用户改变方向。对有明确科学依据或用户最终确认的选择，仍应及时执行；但 agent 需要承担独立审查责任，尤其要指出仅凭短期曲线、显存百分比或焦虑驱动频繁调参的风险。

## When To Use

用于正式训练运行期间的模型结构、loss、优化器、学习率调度、batch、卡型、重启、停止或 producer 替换请求。普通只读监控、明确 OOM/Traceback 恢复和不改变科学语义的日志修复不需要额外阻断。
