## 0. 本轮目标

本轮不是继续扩张 sparse refine 方案，而是**保守收口**并补一个针对 pseudo 监督的几何后置头：

1. **撤掉 delta-loss 中基于 `p_best` 的 preservation 路径**，只保留 ranking。
2. **清理 wrapper ↔ loss 之间的冗余参数传递**，避免继续把 `p_best` / `base_logit` / `w_pos` 之类历史遗留接口往下游带。
3. 在 `Stage1AtomHead` 的 **pseudo 后置分类头** 前，新增一个**one-way、real→pseudo、pseudo↔pseudo 隔离**的稀疏几何聚合头。
4. 几何聚合头除 real hidden 外，再额外吃 **detach 后的 real bind probability** 作为局部先验。
5. 主实验配置打开该几何头；新增一个消融：**保留 P 监督，但关闭几何头，仅用原始 pseudo MLP 做监督**。

## 1. 已确定且不可回滚的设计决策

### 1.1 delta-loss 收口策略

本轮明确不再做 preservation，只保留 pairwise ranking：

- 删除 `p_best` 驱动的正例保留逻辑。
- `LigandSparseRefineDeltaLoss` 语义收口为 **ranking-only auxiliary loss**。
- 候选集侧若仍需要 `p_best` 做 candidate 选择，这是 candidate-set 自己的事；**delta-loss 不再消费它**。

原因：`p_best` 随 epoch 波动较大，作为 preserve 阈值不稳，难以校准，且会把 wrapper / loss 契约重新耦合起来。

### 1.2 pseudo 几何聚合头的结构约束

几何头的约束已经固定：

1. **real→pseudo 单向**：真实原子为上下文，P anchor 为 query。
2. **pseudo↔pseudo 隔离**：不建立 P-P 边。
3. **detach_real_feat 为可配开关**：默认开，即几何头默认只读 real hidden。
4. **real bind prob 恒 detach**：它是静态先验，不应让 pseudo 监督反向塑形 real logits。
5. **几何头只作用于 pseudo back logits**：
   - 作用位置：`pseudo_logit_head` 之前。
   - 不改 `pseudo_feature` 的返回值语义。
   - 不影响 front pseudo head。
   - 不直接改 refine 路径消费的 `pseudo_feature`。

### 1.3 实现形式

选择 **半径截断的稀疏 cross-attention**，不是 dense attn，也不是 pseudo-pseudo 图卷积：

- 邻接：`torch_cluster.radius`。
- 按 pseudo 聚合：`torch_scatter.scatter_softmax` + `scatter_sum`。
- K/V 输入：`[real_hidden, relative_coord, detached_real_bind_prob]`。
- Q 输入：`pseudo_feature`。
- 输出投影零初始化，保证初始时尽量接近 identity 增量。

### 1.4 邻域超参

- 半径：**4.0 Å**。
- 邻居上限：讨论中最终接受的是 **K=48**，这是本轮应遵守的设计值。
- 若代码/配置中仍残留 `64`，视为待修漂移，不视为最终设计。

## 2. 与旧计划的关键偏差

相对 `最后重构代码.md`，本轮有三处关键收口：

### 2.1 A3 消融含义变化

旧计划中的 A3 是“关闭 delta-loss（preservation + ranking）”。

现在 A3 应改写为：

- **关闭 ranking-only delta-loss**，退回纯 `L_cls` refine。
- 不再提 preservation，因为该路径已被整体移除。

### 2.2 主实验的 pseudo 监督更强，但范围更窄

旧计划强调 `pseudo_feature` 深监督本身；本轮在其上新增一个更保守的后置增强：

- 保留原始 pseudo head 监督。
- 新增几何后置头只改 **pseudo back logits**。
- front pseudo head、refine 用的 `pseudo_feature` 都保持原契约。

这样新增能力尽量局限在“最终 pseudo 判别”这一步，而不是把几何聚合揉进 trunk / refine 主路径。

### 2.3 新增 A8 消融

新增：`CPC_A8_pseudo_mlp_only`

语义：

- 保留 P supervision。
- 关闭 `enable_pseudo_geo_head`。
- 用来隔离检验：几何后置头是否优于“只用原始 pseudo MLP 后置头做监督”。

## 3. 代码落点（本轮真实改动面）

## 3.1 `src/model/stage1_atom_head.py`

目标：在不破坏原有 real logits / pseudo_feature 契约的前提下，给 pseudo back classification 增加 one-way 几何聚合增量。

当前应有结构：

1. 可选导入 `torch_cluster` / `torch_scatter`，避免本地无依赖时模块顶层直接炸。
2. 新增 `PseudoGeometricAggregation`：
   - radius 建图
   - relative coord + detached real bind prob
   - 稀疏 cross-attn 聚合
   - 零初始化输出投影
3. `Stage1AtomHead.__init__` 新增配置项：
   - `enable_pseudo_geo_head`
   - `pseudo_geo_radius`
   - `pseudo_geo_max_neighbors`
   - `pseudo_geo_num_heads`
   - `pseudo_geo_detach_real_feat`
4. 启用几何头时做 fail-fast：
   - 必须同时启用 `enable_pseudo_ligand_head`
   - 必须同时启用 `enable_atom_head_back`
5. `forward()` 顺序调整为：
   - 先算 `atom_hidden`
   - 切 real / pseudo
   - 先算 `atom_logits`
   - 用 `sigmoid(atom_logits)` 生成 detached `real_bind_prob`
   - 若几何头开启，则仅对 `pseudo_cls_feature = pseudo_feature + geo_delta`

   - 返回的 `pseudo_feature` 保持不变

## 5. 本轮必须核验的工程点

### 5.1 契约不破坏

重点核对以下不变量：

1. `pseudo_feature` 仍是 refine 消费的那条特征，不被几何头改写。
2. 几何头只影响 `pseudo_logits`，不影响 front pseudo head。
3. real-only 路径不触发 pseudo 相关分支。
4. zero-neighbor 时几何头返回零增量，不应报错。
5. 本地缺 `torch_cluster` / `torch_scatter` 时：
   - 模块可导入
   - 只有真正启用并执行几何头时才报依赖错误

### 5.2 维度与掩码一致性

必须逐项核对：

- `real_hidden` 与 `atom_logits` 的 real 顺序完全一致。
- `real_bind_prob` 形状是 `(N_real, 1)`，与 edge gather 兼容。
- `point_state["batch"]` 在 mixed layout 下与 `pseudo_mask` 切分后的顺序一致。
- `torch_cluster.radius(x=real, y=pseudo, ...)` 返回的边索引解释方向正确：
  - `idx_real = edge_index[0]`
  - `idx_pseudo = edge_index[1]`

### 5.3 配置和实现一致性

必须检查并修正：

- 用户已接受 `K=48`，不能让代码/配置默默停在 `64`。
- A3 / A8 注释文字不能继续残留旧语义。
- `default.yaml` / `CPC_main.yaml` / `A8.yaml` / 代码默认值要保持一致。

### 5.4 CPE 邻域浪费提醒

用户要求在计划中声明：若 `point_clipbig` 或相关点云网络里的 CPE / pointconv 邻域上限存在明显浪费，应保守记录并后续核验。

本轮处理原则：

- 先核对配置与代码中 `pointconv_block_max_neighbors`、CPE receptive-field 的真实消费路径。
- 只有在代码层面能确认“上限经常远大于实际邻域且确实带来显存/算力浪费”时，才把它当成明确问题写入结论。
- 不凭印象下结论。
