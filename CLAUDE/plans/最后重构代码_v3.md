## 0. 背景与总目标

Pocket_Plus 的 Stage1 模型在一个 receptor 体素密度图（BOX）上预测配体结合口袋。主干（trunk）= 体素 backbone + 点云 backbone + voxel→point 融合；其后是若干判别头，对**真实原子（real atom）**和**伪原子 / P anchor**做分类，再由 **sparse refine head** 在候选体素（C）上做精修，端到端指标是 `val_score/global/refined_F1`。

当前判别路径里堆叠了过多历史机制（重 attention stack、前置/后置双分类头、几何聚合死代码、mask 裁边族、调试用 outputs 等）。本轮目标是把最终判别路径收成一条短、可解释、可分阶段冻结增量训练的链路：

```text
voxel backbone
  -> point backbone / voxel-point fusion              # trunk
  -> real / pseudo 两个轻量最终分类头
       每个头内含一个零初始化 cross-attn 子模块（before -> after，纯残差）
  -> sparse refine head（吃冻结 trunk 的 P/C 特征；默认同时吃 before + after）
```

并把训练拆成**三阶段冻结级联**（每阶段只载上一阶段的模型权重、冻得更多），使 trunk、cross-attn、refine 的消融分别落在便宜或免费的位置。

本轮**不做**：大规模全模型联合重训（阶段一的 4 个 trunk 本就从头训除外）、改数据 label 体系、改 candidate 选择算法本身（只加候选下限防护）。

## 1. 代码现状（改之前必须知道的事实）

以下为当前仓库实际状态，已逐项核对。

### 1.1 分类路（`src/model/stage1_atom_head.py` + `src/model/stage1_model.py`）

`stage1_atom_head.py::Stage1AtomHead` 当前是一个"重 atom head"，forward 里依次：

- `atom_tokens` 组装：当 `append_coord_mask=True` 时把 `point_feat` 与 centered-world 坐标、监督 mask 拼成 token。**实际上主配置 `configs/model/atom_head/stardard.yaml` 与 `none.yaml` 里 `atom_head_append_coord_mask` 恒为 `false`**，故这条拼接是死路径，`atom_tokens = point_feat`。
- `atom_token_proj`：token 投影到 `hidden_dim`（可按 typed-point 分 real/pseudo 两套）。
- `Stage1SerializedAttentionStack`：**5 层 PTV3 `Block`** 的共享 attention（`atom_head/stardard.yaml: atom_head_num_layers=5`）。这是要删的"重 block"。
- `real_atom_logit_head`（后置头）：real 槽位 → `atom_logits`。
- `pseudo_feature_head` → `pseudo_logit_head`（后置头）：P 槽位 → `pseudo_logits`；可选 `pseudo_geo_head` 几何聚合。
- `density_residual`：P 特征上的 density cube 直通残差，由 `pseudo_density_residual` 控制，**`configs/model/detach_residual/max_detach.yaml` 里恒为 `false`**，死开关。

同文件还有两个几何聚合类：

- `PseudoGeometricAggregation`（**V1**）：**全项目无任何实例化**，且内部 `idx_real/idx_pseudo` 与 `torch_cluster.radius` 的 row/col 约定取反，是**错误且死的代码**。
- `PseudoGeometricAggregationV2`：当前唯一被实例化（`enable_pseudo_geo_head=True` 时作为 `pseudo_geo_head`）。它是 P 为 query、real 为 source 的单向几何 cross-attn：radius 建图、source detach、relative coord、可选 bind probability、scatter-softmax、**输出投影零初始化**。本轮保留它的实现思想，改造成统一模块。

**前置头**在 `stage1_model.py` 里：直接接在 `outputs["point_feat_raw"]` 的 real / P 槽位上，产出 `atom_logits_front` / `pseudo_logits_front`（`pseudo_logit_head_front`）。于是当前是"前置 + 后置"双分类头体系，配套一堆开关：`enable_atom_head_front` / `enable_atom_head_back`、`atom_loss_front_weight` / `atom_loss_back_weight` / `pseudo_loss_front_weight` / `pseudo_loss_back_weight`。

`stage1_model.py` 的 forward 输出字典（`outputs`）当前约 **34 个 key**，混了三类：(a) 下游真要用的（`atom_logits`、`pseudo_logits`、`pseudo_voxel_zyx`、`pseudo_batch_index`、refine 相关）、(b) 监督/几何/归属字段（`atom_target`、`atom_valid_mask`、`atom_counts`、`atom_coord_local_voxel`、`atom_is_in_core_box`、`atom_global_indices`）、(c) 纯调试残留（`atom_tokens`、`atom_hidden`、`atom_logits_front`、`pseudo_logits_front`、旧名 `pseudo_feature`）。

`enable_interface_norm=True` 时，`stage1_model.py` 在四处放 `nn.LayerNorm`（voxel→point 融合两源、embed→point、density→point；`interface_norm_real_density_to_point` 把真实原子 density 喂进 point 特征）。注意：**这些是 LayerNorm，无 running statistics。**

### 1.2 Sparse refine head（`src/model/sparse_refine/sparse_refine_head.py`）

构造签名含 `P_point_backbone_dim` / `P_atom_head_dim` / `P_voxel_backbone_dim` 与一个 `inputs` 开关字典。当前 P 侧两路特征：

- `P_point_backbone_feat`：P 的 final point backbone 特征（语义上即"cross-attn 之前"的 P 特征）。
- `P_atom_head_feat`：P 的旧 atom head `pseudo_feature`（语义上是"经过 atom head 处理后"的 P 特征）。

另有 `P_voxel_backbone_feat`、`C_voxel_backbone_feat`、`use_voxel_logits`（C 原始 ligand logits）、`use_candidate_class_embedding`、`use_relative_coords`。每个启用源各有 `interface_norm_*` LayerNorm；输出增量零初始化。**refine 不吃任何真实原子特征**（只吃 P + C/voxel）。

### 1.3 候选截断（`src/model/sparse_refine/candidate_set.py` + `src/wrappers/voxel_point_stage1.py`）

`adaptive_threshold` 模式按 best-F1 阈值 `p_best` 选候选 C：

```text
n_best_box        = count(prob_valid > p_best[class])
target_before_cap = ceil(n_best_box * adaptive_expand_factor[class])
target_count      = min(target_before_cap, max_candidate_voxels_per_class[class], numel)
```

`p_best` 由 wrapper 在每次 validation 用 F1–阈值网格搜索取 argmax-F1 阈值，然后**硬替换** cache（`voxel_point_stage1.py` 中 `self._cached_voxel_ligand_p_best_by_class = p_best`），并存进 checkpoint。主配置：`configs/model/task/binary.yaml` 的 `adaptive_expand_factor=[5.0]`、`max_candidate_voxels_per_class=[25000]`。已知问题：argmax-F1 阈值在曲线顶端平坦时会在相邻 ckpt 间大幅跳变（0.7↔0.3），使候选数偶尔崩塌。

### 1.4 Mask 裁边族（`src/datasets/box_geometry.py` + `box_sample_builder.py`）

`build_box_point_numpy_sample` 产出 `atom_is_in_core_box`（原子是否在 BOX core 内；原子按 `atom_buffer_radius` 多选了一圈 BOX 外 buffer 作上下文）、`voxel_valid_mask`、`atom_valid_mask`。后两者由 `valid_crop_margin` 控制裁边：只有落在裁掉 margin 后的区域内的体素/原子才参与监督。**已核对：所有现役 dataset 配置（`configs/dataset/emb_unet.yaml`、`unet*.yaml`、`MINI_emb_unet.yaml`）里 `valid_crop_margin` 恒为 `0`**，故裁边在主线是恒等操作，但仍拖着 `voxel_valid_mask` / `atom_valid_mask` 及大量临时变量在 dataset → collate → wrapper → loss → `src/inference/parse_input.py` 全链路传递。

关键事实：**体素网格就是 BOX 本身，没有 buffer**；只有原子才有"core 内 vs buffer 外"之分。所以体素侧从来不需要 core-box 子选择——整张 BOX 的全部体素都参与监督。

### 1.5 训练与 checkpoint（`src/train.py` + `configs/train/B40_L3.yaml`）

- ckpt 保存：`ModelCheckpoint(filename="TOP_epoch_{epoch:02d}_score_{<monitor>:.4f}", dirpath=<run_dir>/checkpoints, save_top_k=cfg.output.save_top_k, save_last=True)`，外加可选 `PERIODIC_*`。`monitor=cfg.model.monitor_metric`（主配置 `val_score/global/refined_F1`，mode=max）。
- 优化器：`AdamW(lr=3.0e-5, weight_decay=0.01)`。
- 调度器：`warmup_plateau`（自定义 `WarmupThenReduceLROnPlateau`）：LinearLR warmup（`warmup_ratio`，`warmup_start_factor=0.33`）后接 ReduceLROnPlateau（`factor=0.5`、`patience=3`）。按主指标每次 validation 衰减。原训练末期经多次 plateau 衰减后 lr 会降到峰值的 1/(2^k)。
- **当前没有**"只载模型权重、不恢复训练状态"的入口，也**没有** `init_from` / `frozen_module` / 冻结调度 / 自动选最优 ckpt 的通用逻辑。
- 服务器侧调度脚本 `sbatch/_train_core.sh` 已具备"任务成功结束后挂起不退出、连续执行下一条命令"（TRY_AFTER_END）等能力，**串行链路由它负责**，本方案不另写编排循环。

## 2. 目标结构：最终分类头

### 2.1 统一几何 cross-attn（两方向复用同一个类）

新增单一模块（沿用 `PseudoGeometricAggregationV2` 的实现思想）：

```python
GeometricCrossAttention(query_channels, source_channels, num_heads, radius,
                        max_neighbors, detach_source_feat, act_layer)
```

要点：radius 建图、source 特征 detach、relative coord、可选 bind probability、scatter-softmax、**输出投影零初始化**。实例化两次：

1. `real_to_pseudo`：query = P，source = real（可吃 detached real bind prob）。
2. `pseudo_to_real`：query = real，source = P。

**接线契约（硬性，必须有单测）**：

- 以**纯残差**加回：`feat_after = feat_before + crossattn(...)`，中间不得插 LayerNorm 等破坏逐元素恒等的算子。
- 因输出投影零初始化 + 纯残差，**cross-attn 处于零初始化或被冻结态时，`feat_after == feat_before` 逐元素精确成立**。这是三阶段训练能"免费"对照 cross-attn 的基础（§6）。

推荐超参：`interaction_radius=4.0`、`interaction_max_neighbors=48`、`interaction_num_heads=4`、`interaction_detach_source_feat=true`。零初始化写进代码逻辑，不做可选开关。**不再提供"关闭 interaction"的运行期开关或独立消融配置**——它由阶段一/阶段二的相位天然给出。

### 2.2 轻量分类尾部

固定命名 `real_atom_head` / `pseudo_atom_head`，结构 `LayerNorm -> Linear -> act -> Linear -> logits`：

- `real_atom_head` 输出 `atom_logits`；`pseudo_atom_head` 输出 `pseudo_logits`。
- 末层支持 prior bias 初始化（沿用现有 `prior_prob` / `prior_probs` / `prior_prob_point_ligand`）。
- 若开 receptor base logit 残差，末层零初始化使初值等价 base。
- **不再输出** `atom_logits_front` / `pseudo_logits_front`。

分类头输入：直接消费最后一轮 point backbone 输出，按 `PseudoAtomLayout` 从 `outputs["point_feat_raw"]` 切分为 `real_feat_before_interaction` / `pseudo_feat_before_interaction`。

### 2.3 outputs 清理

在现有 `outputs` 上做减法，不另起命名体系。

**删除**：`atom_logits_front`、`pseudo_logits_front`、`atom_tokens`、`atom_hidden`；旧名 `pseudo_feature` 改为 `pseudo_feat_before_interaction`。

**保留**（归属与坐标字段本轮全部留）：`atom_logits`、`pseudo_logits`；`real_feat_before_interaction` / `pseudo_feat_before_interaction` / `real_feat_after_interaction` / `pseudo_feat_after_interaction`；`pseudo_voxel_zyx`、`pseudo_batch_index`；`atom_global_indices`（推理 scatter 回全局原子，主字段不可替代）、`atom_coord_local_voxel`、`atom_is_in_core_box`、`atom_target`、`atom_counts`；`recycle_passes_used` 等 runtime 字段（归 runtime 分组，§8.3）。

## 4. Sparse refine head 重构

### 4.1 输入重命名与默认值

P 侧两路 re-wire（拼接 MLP 管线不变）：

- `P_final_point_feat`：P 的 before-interaction final point 特征（即原 `P_point_backbone_feat`）。
- `P_after_interaction_feat`：P 经 `real_to_pseudo` cross-attn 后、**再强制 detach** 的特征（即原 `P_atom_head_feat` 那一路）。由 `use_P_after_interaction_feat` 控制，**默认 `true`**。
- `P_voxel_backbone_feat`、`C_voxel_backbone_feat`、`relative_coords`、`candidate_class_embedding` 照旧。
- `use_voxel_logits` **改名 `use_C_voxel_logits`**。

配置 `inputs`：

```yaml
inputs:
  use_C_voxel_backbone_feat: true
  use_P_final_point_feat: true
  use_P_after_interaction_feat: true    # 默认开；本轮不作消融
  use_P_voxel_backbone_feat: true
  use_relative_coords: true
  use_candidate_class_embedding: false
  use_C_voxel_logits: true
```

删除 `use_P_atom_head_feat`；构造参数 `P_atom_head_dim -> P_final_point_dim` / `P_after_interaction_dim`；错误信息、文档同步改名。

### 4.2 解耦不变量

`P_after_interaction_feat` 始终 **detach**：refine 损失不回传 cross-attn。又因 cross-attn 在阶段三已冻结（来自阶段二），refine 的全部输入在阶段三内是**固定只读**，stage 间确定、可串行。单测断言：after 路对 cross-attn 参数的梯度为 None / 零（detach 生效）。

### 4.3 零初始化

refine 关键输出增量零初始化（residual 末层 / direct 模式新增 delta / prior bias 或 base-copy 保证初始稳定）。零初始化是实现契约，不做消融开关。

## 5. 候选截断防护（p_best 逻辑不动）

`p_best` 的计算与更新**完全保持现状**（validation argmax-F1 → 硬替换 cache）。仅新增"单 BOX 候选下限"防护，抑制 `p_best` 抖动导致候选数崩塌：

- 新增配置 `min_candidate_voxels_per_class`，**默认 `[5000]`**，per 候选类（与 `max_candidate_voxels_per_class` 对称）。
- **仅作用于 `adaptive_threshold` 模式**（warmup 走 fixed top-c、topk 走 max_count、recorded 暂不用）。
- 公式（`5000 < 25000` 故防护有效；撞硬上限或可用体素数时上限优先）：

```text
target_count = min( max(target_before_cap, min_floor), max_candidate_voxels_per_class, numel )
```

BOX 可用体素不足 5000 时全取。

## 6. 三阶段冻结级联训练

口头上是"两阶段"，实际是三阶段（trunk → cross-attn → refine），统称**三阶段训练**。

### 6.1 阶段定义与冻结表

模型**始终构建完整体**（trunk + 两头含零初始化 cross-attn 子模块 + refine），**所有参数恒注册**，只用冻结名单控制可训，不做条件注册。⇒ 每次跨阶段加载 `unexpected=0`、`missing=0`。

| 阶段 | 配置目录 | load | 解冻（训） | 冻结 | loss | 产物 |
|---|---|---|---|---|---|---|
| **一** | `CPC1` | 随机从头 | trunk + 两头分类尾（读 before） | cross-attn（锁零）、refine | atom + pseudo（+深监督） | `stage1-best` ×4 trunk |
| **二** | `CPC2` | `stage1-best` | cross-attn + 两头分类尾 | **trunk**、refine | atom + pseudo | `stage2-best`（主 trunk） |
| **三** | `CPC3` | `stage2-best` | refine head | trunk、两头、cross-attn | 仅 refine 损失（§7.1） | 多个廉价 run |

- 阶段一是唯一"贵"的阶段（trunk 全训），跑 4 个 trunk 配置；阶段二、三都在冻结 trunk 上只训小模块，廉价、可串行。
- 阶段二默认**同时训 cross-attn + 头分类尾**（让头适配 `delta`）。
- 冻结用 name-pattern。trainable 名单含对应模块及其 LayerNorm/projection/bias；接口 norm（LayerNorm，无 running stats）随所属阶段一起冻/训，不单独处理。
- 阶段三 loss 只保留 refine 损失（atom/pseudo 头已冻，监督它们无意义）。

### 6.2 `train.py` 通用化（不写任何编排包装）

把"从 ckpt 继承 + 冻结 + 新调度"做成 `train.py` 的**通用能力**，由配置驱动：

1. **`init_from`（可选）**：可填 `.ckpt` 文件，或一个含 ckpt 的 run 文件夹。
   - 给文件夹时，自动取该文件夹下的最优 ckpt。**为了真正通用、不依赖文件名解析，`train.py` 在保存 ckpt 时额外维护一个全局 `BEST.ckpt`**：新增一个 `ModelCheckpoint(filename="BEST", save_top_k=1, monitor=<同主指标>, mode=<同>)`，始终覆盖为当前最优；保留现有 `TOP_*` / `PERIODIC_*` 仅供查看。于是"给文件夹自动选最优" = 直接取 `<folder>/checkpoints/BEST.ckpt`，无需解析文件名。
   - **只载模型权重**，不恢复 optimizer / scheduler / global_step。
   - 启动打印：ckpt 路径、loaded/missing/unexpected **计数**（不 dump key 名）+ trainable/frozen 参数计数 + trainable 模块名摘要。**跨阶段加载预期 `unexpected=0`、`missing=0`**。
2. **`frozen_module`（可选，新配置组 `configs/frozen_module/*.yaml`）**：只放冻结 name-pattern；命中的参数 `requires_grad=False`，其余可训。
3. **`***` 哨兵回退（`train.py` 中唯一允许的非通用逻辑）**：若 `init_from` 写成 `"***"`，则打印**显眼警告**并根据 job-id 自动补全上一阶段产物文件夹（再取其 `BEST.ckpt`）。**"如何由 job-id 推导文件夹"的逻辑不写在 `train.py` 内，放到独立模块（如 `src/utils/ckpt_resolve.py`），`train.py` 仅 `import` 调用。** job-id 由 `_train_core.sh` 经环境变量（如 `SLURM_JOB_ID`）提供；具体推导规则按实际 run_dir 命名约定实现。
4. 顺手清理 `train.py` 内的死代码，确保其余逻辑全通用。

**这套能力足以满足"一行命令"需求，不需要任何额外包装层。** 三阶段各是一条 `_train_core.sh ... "<hydra overrides>"`：

```text
阶段一: +experiment=CPC1/trunk_main        frozen_module=stage1
阶段二: +experiment=CPC2/heads             init_from=<stage1_dir|***>  frozen_module=stage2
阶段三: +experiment=CPC3/refine_xxx        init_from=<stage2_dir|***>  frozen_module=stage3  +train=small_increment
```

串行与"配对/网格"由 `_train_core.sh` 钩子负责（用户可预写多条一行命令，对未知的上一步产物用 `***` 占位）。

### 6.3 小训练（阶段二、三）的 lr 调度

阶段一（贵、训纯 trunk）沿用现有 `warmup_plateau`。阶段二、三的小增量训练仍用 `warmup_plateau`，但参数改为：

- `warmup_steps`（或比例）= 0 或接近 0。
- `patience = 1`（第 2 次验证不升即降 lr）。
- **第 2 次降 lr 即停止训练**（不是默认的 4 次）。Lightning 无现成"降 N 次即停"开关，故在 `train.py` 加一条**通用规则**：统计 lr 下降次数，达到 `cfg.train.scheduler.stop_after_lr_reductions` 即 `trainer.should_stop=True`；`null` 表示禁用（阶段一用 `null`）。
- 整套落到 `configs/train/small_increment.yaml`，一行命令 `+train=small_increment` 继承。

## 7. 消融

### 7.1 阶段一 trunk 消融（4 个并列、各自从头训，落 `CPC1`）

| 配置 | 改动 |
|---|---|
| `trunk_main` | 主配置（fusion=e234d4、体素 gauss27+5D、density=both 含真实原子 density） |
| `trunk_no_real_density` | 去真实原子 density box（`density_cube: pseudo`；该路经 `interface_norm_real_density_to_point` 进 point 特征，属 trunk 级） |
| `trunk_hard_scatter` | 体素输入改最朴素 hard scatter（`online_pdb_feature_scatter_kernel: legacy`、关 occupancy/centroid；通道数与 voxel backbone 输入同步校验，不闭合先补配置组、不在代码静默兜底） |
| `trunk_decoder_fusion` | `/model/fusion: d4321`（decoder 侧 hook；独立从头训，非冻结换 hook） |

判优：按各 trunk 的 `stage1-best` 分类质量（atom / pseudo 指标、`pseudo_PRAUC`）择优；只在最优 trunk 上做阶段二、三，其余 trunk 停在阶段一。

### 7.2 cross-attn 消融（阶段一 vs 阶段二，免费）

`stage1-best`（cross-attn=0，无 interaction）对照 `stage2-best`（cross-attn 训过）。同一冻结 trunk，严格可分，无需任何独立消融配置。

### 7.3 阶段三 refine 网格（落 `CPC3`）

两轴全因子 **3 × 3 = 9**：

- 损失种类：`tversky` / `tversky + focal(γ=0 ≡ BCE)` / `tversky + rank`。
- 正负权重（统一"正类:负类强调"旋钮）：`7:3` / `8:2` / `9:1`。

`use_P_after_interaction_feat` 固定为 `true`，**不作消融轴**。

## 8. Loss 与日志

### 8.1 阶段三 refine 损失

- **不新增 loss 类**，只改 `AdaptiveClassificationCompositeLoss` 现有参数（以代码当前字段为准）。`γ=0` 即 focal 退化为 BCE。
- refine 仍是 C 级分类项 + 可选 ranking 辅助项（`ligand_sparse_refine_loss` / `ligand_sparse_refine_delta_loss` / `ligand_sparse_refine_w_rank`），注释与命名适配新结构。
- 正负权重映射：tversky 的 α/β（FP vs FN）、rank 的正负、BCE 的 `pos_weight` 共用同一比值。

### 8.2 P 自身分类能力日志

只新增 `val_score/global/pseudo_PRAUC`（复用 wrapper 已有的 `_sample_ligand_pseudo_supervision()`）。**不实现 accuracy 类指标**。二分类不加 `_foreground` 后缀；不重写 CPC diagnostics、不改 candidate 中间产物面板。

### 8.3 日志归类（移动，不删除）

`train_loss` 面板只留 loss 与 loss 权重；`recycle_passes` 等 runtime 字段移到 runtime 分组（移动非删除）；删 front/back 相关 loss 与 metric；不大搬 CPC 采样中间产物（candidate 数、anchor 数、cap 前后统计、p_best/p_sampling、refined/unrefined 诊断），保持现有面板与命名，除非 front/back 清理被迫连带改名。

## 11. 验收

**结构**：主线无额外 atom attention stack；全项目无 front/back 语义、无 `atom_logits_front`/`pseudo_logits_front`、无 `atom_tokens`/`atom_hidden` wrapper-facing 输出；`stage1_atom_head.py` 只剩统一 cross-attn + 轻量分类尾 + 辅助；无 V1 几何聚合、attention stack、token 组装、density residual；无 `valid_crop_margin`/`atom_valid_mask`/`voxel_valid_mask`，原子监督走 `atom_is_in_core_box`、体素全监督；refine 不再依赖 `P_atom_head_feat`。

**单测**：cross-attn 冻结/零初始化态 `*_after_interaction == *_before_interaction`（逐元素）；refine 的 after 路对 cross-attn 参数梯度为零（detach 生效）。

**训练**：能 model-only 从 ckpt / 文件夹（`BEST.ckpt`）/ `***` 哨兵初始化；跨阶段加载 `unexpected=0`、`missing=0`；trainable 名单恰为该阶段计划模块；零初始化模块启动增量 ≈ 0；阶段二、三按 small_increment 调度，第 2 次降 lr 即停。

**日志**：`train_loss` 只含 loss 与权重；runtime 字段归 runtime 分组；CPC diagnostics 不被大搬家；新增 `pseudo_PRAUC`。

**实验**：阶段一 4 个 trunk 跑完、择优；`stage1-best` vs `stage2-best` 给出 cross-attn 对照；阶段三至少跑通 9 网格的主要单元；每 run 看 candidate recall、unrefined F1、refined F1、refined−unrefined、`pseudo_PRAUC`、训练稳定性。

## 12. 实现期纪律

- **过期测试就地重写**：所有测试代码都有过期风险（可能断言早已无效的旧逻辑）。遇到的若是测试与新结构不兼容（而非真实代码 bug），**改写/重写旧测试，不得为迁就旧测试在主线加兼容垫片**。
- **不留兼容分支**：删的旧模块/字段直接删，旧实验复现从 git 历史或独立 legacy 文件恢复。
- **顺手清死代码**：触及的文件（尤其 `train.py`）内的死代码一并清理。
- **权威层级**：本文与实际代码/配置/产物冲突时，以后者为准，把冲突当待修 bug 或待更新文档。
